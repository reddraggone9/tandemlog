# External task migration and canonical Markdown

This developer tool reads an authorized copy and writes only a **new staging folder**. It never modifies the source or an existing app folder. The app remains the source of truth after migration; formatting from the old file is deliberately not retained.

```sh
dart run tool/migration.dart dry-run COPY.md NEW_STAGING_DIRECTORY 'Imported user' [IMPORT_BATCH_UTC]
dart run tool/migration.dart export STAGING_DIRECTORY NEW_OUTPUT.md
dart run tool/migration.dart audit-recurrence STAGING_DIRECTORY 2026-10-20 NEW_AUDIT.json
```

All commands refuse existing outputs. Export and audit outputs must be outside the resolved canonical data directory (including directory-link aliases); these operations cannot add files to the workspace they read. The dry-run parser keeps only transient functional fields for comparison. Canonical logs contain normal `user.created`, `task.created` and date-only historical `task.completed` events—no original file, import-document event, source fields, formatting, line mappings or provenance. Opaque wiki/Markdown links remain part of task titles. Source hashes and source bytes are not written into events; hashes are used only as inputs to deterministic IDs.

Import captures one UTC batch time. The clock starts at epoch nanoseconds derived from actual runtime microsecond precision and advances by one for each event; exact decimal-string clocks use BigInt arithmetic within signed 64-bit bounds. This is import time, never an invented historical completion instant. Reusing identical source bytes, user mapping and explicit batch time yields identical RFC UUIDv5 identities/events; another batch time creates a separate run. Scalar JSON-number and tuple-clock drafts are rejected.

## Canonical format

Output is UTF-8 without BOM, LF, one final newline per task, in **current shared manual order**. Each row has fixed metadata order:

```text
- [ ] Title #alphabetically-sorted-tags #start-time-0930 🔁 every week 🏁 delete 🛫 2026-10-01 ⏳ 2026-10-02 📅 2026-10-03
- [x] Completed title ✅ 2026-10-03
```

Optional fields are absent when unset. Titles retain genuine internal whitespace and opaque links. Ordinary tags are membership sets, so duplicates collapse; spelling/case remain intact. Time tags map only to the floating start time. Every **open recurring** row exports with `🏁 delete`; completed rows receive no forced flag. The app retains completed history for all tasks: source delete flags controlled Markdown clutter, not app deletion. Import counts this intentional adaptation in its transient report.

The exporter consumes only current projected domain fields using the same projection/order functions as the app. It handles representable title/tag/date/recurrence edits, manual moves, completion/reopening and generated successors. It reparses its canonical output and compares task semantics and order; it never consults original source syntax. The import report compares canonical bytes with input bytes and reports `sourceByteExact` truthfully, but byte equality is not promised or needed when original formatting differs. A private diff can be generated by the local operator; no original formatting is stored to force the diff away.

## Explicit limits and incomplete history

Import rejects **nonblank non-task lines** with a line diagnostic rather than dropping notes/headings. Blank lines, BOM, line endings and metadata spacing are cosmetic canonicalization. Unknown metadata, statuses/rules, malformed dates, nested tasks and times without dates fail explicitly. No source repair is attempted.

This Markdown syntax cannot currently represent task descriptions/notes, scheduled/due time-of-day, pinned time zones or precise completion timestamps. Export rejects these, including midnight ISO datetime completion values; only an actual date-only completion field maps to `✅`. It also rejects multiple assignees, unrepresentable tag syntax and titles that would be reinterpreted as task metadata. Single-assignee identity is reported outside Markdown; import into a chosen user is an explicit mapping, not preservation of a user ID inside the file.

Export requires complete resolvable history: invalid streams, orphan edits, missing/invalid assignees, completion/tag references and move anchors fail. Symlinked/nonregular canonical logs or manifests are rejected, not skipped. An entirely absent independent writer with no references cannot be inferred from an ID-only manifest; the operator must ensure folder synchronization is complete before export. Missing context is never repaired or mutated by this tool.

## Read-only recurrence audit

The audit emits the agreed oracle input: `completion` and `cases` containing task IDs/current positions, rules, input dates and predicted next dates. It includes completed repeating history, but creates no completions or successors. Aggregates include recurrence/form/date/time counts; titles, tags and links are excluded. Compare separate reports for chosen completion days with the independently pinned Obsidian Tasks oracle. These predictions alone are not independent recurrence verification.

Keep real-source reports, diffs and exports private. Before cutover, verify source inventory, semantic comparison, recurrence-oracle results and the staged app behavior, then approve the concrete destination. Sanitized tests do not establish that the private source has passed.
