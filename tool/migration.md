# One-time Markdown rehearsal

This is a separate developer tool, not an app importer. The actual source and any live task folder remain untouched. Run only on a copied, authorized source and select a **new private staging directory**. The staging folder contains canonical JSONL and can subsequently be opened by the matching protocol-v2 app for rehearsal; it is not an automatic cutover.

```sh
dart run tool/migration.dart dry-run COPY.md NEW_STAGING_DIRECTORY 'Imported user'
dart run tool/migration.dart export NEW_STAGING_DIRECTORY NEW_RECONSTRUCTED.md
```

Both commands refuse existing outputs. A dry run validates every event using the app's shared validator, independently projects the task records, and verifies exact source bytes before writing a destination. Source bytes are reread before writing to detect concurrent changes. The import captures one UTC batch time, stored as the wall-millisecond component of every event's hybrid logical clock; successive logical components preserve source order. This is the import time, never a fabricated historical task timestamp. Source completion dates retain date precision. A dedicated writer and entity identifiers derive deterministically from source bytes, user mapping, parser version and that batch time. Duplicate titles remain separate because identity includes source position. Repeating the same rehearsal in another new directory with the same explicit UTC batch time produces identical events. The command prints `importBatchTime`; retain it for deterministic retries, passing it as the optional final argument (after user name), for example `2026-10-01T12:00:00.000Z`. Omitting it captures a new time and creates a distinct import run/writer. Old scalar-clock logs are rejected explicitly. An interrupted destination is preserved for investigation; retry into another new directory, never point this tool at a live folder.

## What is preserved

UTF-8 (with or without BOM), mixed LF/CRLF/CR endings, final-newline presence, flat open/checked task lines, source order, whitespace, duplicate tag occurrences, opaque wiki/Markdown links, separate start/scheduled/due/completed dates, floating `#start-time-HHMM` values with explicit start dates and the observed recurrence expressions. The observed source has no scheduled-time or due-time metadata; those optional app fields import as null. Adding either later is a semantic edit and blocks unchanged-source export. Completed repeating imports remain history and do not create successors. Reserved start-time syntax maps to the schedule alone; ordinary tags do not retain a second, editable copy of the time.

Recognized source maps live in canonical `import.document` events. Each line has formatting spans and semantic slots, linked to independently created task entities. Export verifies log-filename/writer binding, checks those tasks against their source mapping, reparses reconstructed Markdown to verify rendered semantics and reconstructs semantic slots from replayed domain fields. It does **not** read a hidden original file or return a single stored source blob. Exact reconstruction therefore requires only the canonical logs and manifest, but the logs include original non-task text and formatting: treat their privacy accordingly before sharing a folder.

## Deliberate limits

The guaranteed byte-exact exporter is for an **unchanged import**. Any task edit, move, removal, addition or completion change is an explicit export error rather than stale output. Edited-document export is a separate feature, not implied by this migration proof. Notes are not inferred from task titles; Markdown links remain opaque title text. The narrow parser accepts flat source tasks, not arbitrary Obsidian vault syntax, custom statuses, nested tasks, malformed dates/times or unknown Tasks metadata. Unknown recurrence suffixes stop the rehearsal. A time without a start date, or a start after its due date, stops with a source-line diagnostic; the importer never repairs dates. Unsupported encodings stop rather than replace characters. Current protocol text/record bounds apply; oversized source/task data stops without writing a destination.

Private source text, hashes, reconstructed files and reports must stay out of the public repository and release assets. Before real migration, the local operator must verify source counts and all field mappings, compare the reconstructed bytes independently, exercise the staged folder in the candidate app, and obtain approval for the concrete final destination. Passing the sanitized fixture tests does not establish that the unseen private source has passed.
