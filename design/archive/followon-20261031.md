persistence, including create/update/completion successors. Existing rules and

floor. Older readers reject revision4 with the existing update-required message

smuggled into an older revision. Revision4 completion retains required exact

against RC109's real `lib/` (git archive of the published commit, separate

completion modes, whole-action refusal with partial tail, warm prefix, Task and

evidence of native old-app behavior.
New clients read all previous history indefinitely. Do not use expanded rules
on shared live data until every installation is updated; a prerelease must not
force RC109 testers off their outstanding candidate without coordination.

Grammar: every 1–999 months on the 1st/2nd/3rd/4th/last weekday; any month list
on ordinal day1–31; every N months on ordinal day1–31; optional when done on each.
Case-insensitive parsing, exact input retained. Missing day31 clamps to the
month's last day, matching existing ordinary monthly advancement. A constrained
rule first considers the anchor month (existing 1st-Friday behavior); when done
anchors on completion. Explain this on-demand, not a permanent banner. Preserve

## Ranked actual defects

1. Repeat example: prefix e.g.; tap opens options; no implicit selected value.
2. F1: retain drafts across unrelated changes, but never silently retarget an
   editor whose selected target set/content diverged. Refuse with a working
   close-and-review action (not Try again). Rebase unrelated changes only when
   every captured target is byte-identical; canonical fresh snapshot and existing
   command guard remain authoritative. Selection/editor title must not disagree.
3. Cold open: neutral opening surface until startup settles; load saved appearance
   before delivering first frame. Error/retry only after an actual failure.
4. Activity: current known target names as advisory context, human local time with
   zone, technical IDs on demand; say user wasn't recorded once, not per row.
5. Move some: exclude current location suggestions; preserve minimum field reveal
   with keyboard/200%; never let suggestion acceptance submit a move.
6. Recurring completion: show successor date when available, no invented schedule.
7. Inbox: hide redundant visible Needs expiration only under Inbox heading; retain
   Search/Retained/Deleted and semantics. CLI Search classifies true Inbox matches.
8. Ancestor EACCES: tolerate only inaccessible opens of pre-existing ancestors;
   mandatory barriers for newly created entries, including failed-barrier retries.
   Preserve accessible first-use ancestry barriers and all fsync failures.
