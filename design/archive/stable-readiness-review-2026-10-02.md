## Findings requiring resolution before stable

1. **P1 — durable creation.** [LocalLogFolder](../lib/storage/log_folder.dart) flushes newly created manifest and writer-log contents, but not their containing directory. On Linux, file `fsync` does not by itself guarantee directory-entry persistence. A sudden system/power failure shortly after an acknowledged first save can therefore lose the newly created file; a surviving cache can detect loss but cannot replace canonical history. This failure was not reproduced by destructive power-loss testing. Implement and verify platform-appropriate durable creation, including writer identity initialization, or explicitly agree on a narrower durability promise. [Primary Linux documentation](https://man7.org/linux/man-pages/man2/fsync.2.html).
2. **Conditional P1 — ambiguous Android document names.** [SAF lookup](../android/app/src/main/kotlin/com/reddraggone9/tandemlog/MainActivity.kt) chooses the first matching display name; [ingestion](../lib/storage/task_store.dart) deduplicates enumerated log names. A provider exposing two same-named canonical documents can leave one divergent history unseen by a warm cache. This is code-supported, not observed on the intended provider. Reject duplicate canonical names during lookup/enumeration, including the manifest, and add a warm-cache divergent-document regression. Do not promise arbitrary providers behave like a unique-name filesystem.
3. **Evidence gaps.** Complete a bounded intended-device/provider matrix for interrupted writes, reboot, permission revocation/regrant, actual synced replacement and subsequent writes. Rehearse complete canonical backup → fresh install/private profile and new writer → restore → new write → peer convergence without loss, before app-authoritative cutover. A supplementary current-runtime Linux synthetic rehearsal now covers this chain and Undo/order in12 checks; it does not cover fresh-install/grant handling or restore/rejoin on the intended phone/provider. Narrower cache rebuild and Markdown round-trip tests alone do not establish that acceptance. Isolated-copy evidence and actual-phone participation remain separate. See the recorded result below. Existing force-stop/SAF replacement and user-reported sync successes are complementary evidence, not substitutes. Retain genuine supported historical cache/protocol fixtures before stable compatibility promises; tests that relabel a current cache's version do not demonstrate every historic layout.
