## Conclusion and scope

The [verified KAPT advisory](https://github.com/advisories/GHSA-r937-wjx7-w2jp) is fixed in stable Kotlin 2.4.20. This is a build-cache deserialization issue, not an application runtime or synced-user-data parser vulnerability. The app, pinned Flutter included build and current Android plugin configurations do not apply KAPT or configure annotation processors/remote build caches. Static absence is not a resolved-task report, and this proposal does not claim every older Kotlin scope is upgraded.

KGP 2.4.20 supports the existing versions under the [published matrix](https://kotlinlang.org/docs/gradle-configure-project.html). Google requires R8 at least 9.1.29 for [Kotlin 2.4 bytecode](https://developer.android.com/build/kotlin-support). The unchanged official AGP 9.1.0 builder JAR embeds `r8-version.properties`: R8 **9.1.31**, revision `60751e845e0a27ed4dd4f3d50e53c9f196fa30bb`. This closes the static minimum check; the effective app receipt also confirms loaded R8 9.1.31.

## Focused source, native payload and hook review

The review compares exact published old/new source archives, then traces JVM configuration, compiler/BTA classloading, daemon launch/loopback transport, Android task registration, reporting, KAPT applicability and inactive platform tool installers. It is a **focused execution-boundary review**, not exhaustive line review of the 512 changed KGP or 2,801 changed compiler source entries. The source-diff inventory discloses that scale. Compiler-runner, FUS, idea/idea-proto and script-runtime source comparisons are identical; commonizer API changes are syntax only. CRI's changed serializer normalizes file-path hash inputs; compiler-reference indexing is disabled by default and consumes private build data.

JVM work loads compiler implementations from dependency-selected classpaths and can start the existing Java compiler daemon through argument arrays, with loopback transport. HTTP build reporting requires an explicit HTTP output/URL; none is configured. FUS persists build metrics locally and is normally suppressed on CI; the isolated evaluation should explicitly disable collection. No new Android/JVM installer registration was found. App `preBuild` still invokes the reviewed repository Python helper and locked offline Rust build.

The signed KGP JAR additionally bundles **Playwright Java 1.61.0 / core JS 1.61.1**, absent in 2.4.0, and 17 browser/OS installer scripts. These include apt/MSI/macOS installation and Windows WSL setup with Node download. Their source registration is scoped to `KotlinJsIrCompilation` browser tests; Android/JVM application does not register that flow. This audit does **not** approve executing those installers or fetching their downstream payloads. Resource hashes and versions are recorded independently of the Maven closure.

The compiler embeds 15 changed **JLine 3.30.16** native libraries. Every byte matches the official upstream JLine JDK8 JAR, whose SHA-256 `a11f8b5b3cf03a7da8d50c91b1c7ed33750562dec1c53566647266c6bcd9a2e0` is also in the exact Kotlin 2.4.20 tag's verification metadata. Reviewed JLine loader source uses explicit properties, embedded extraction into temporary files and `System.load`, with no network installer. Interactive terminal activation is outside the headless JVM compiler evaluation. Twenty other compiler native payloads, including LZ4/Jansi, are byte-identical to the signed baseline. Native provenance/loader review is not C-source exhaustion or a reproducible-binary attestation.

Bundled KGP Gson **2.11.0 → 2.14.0** and added error-prone annotations **2.48.0** are distinct from external unshaded graph Gson 2.11.0 / annotations 2.27.0, which remain unchanged. Official source/metadata and relevant Gson adapter/allocation boundaries were inspected; no install hook exists there. Unchanged shaded Guava, codecs, commons and parser identities are retained in the bundled metadata inventory.
