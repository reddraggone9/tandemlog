# Focused read-only review: Yrs 0.28.0 native spike

2026-10-04. Reviewed `src/lib.rs`, the 34 frozen ctypes contract tests, `tests/cases.json`, and installed Yrs 0.28.0 source. No implementation changes, new probes, broad application test runs, or production adoption. The reported green suite demonstrates the exercised synthetic cases; the findings below are static review conclusions and proposed gates, not newly reproduced runtime results.

## Assessment

Yrs is a credible candidate for a narrowly scoped plain-text merge adapter. The current bridge is deliberately a prototype and should remain so. The main missing gates are document/actor provenance, strict plain-text admission on every ingress, draft ownership and Save lifecycle, and bounded native state. These are more consequential than expanding the existing benign merge permutations.

## Concrete gaps and acceptance gates

1. **Actor uniqueness is checked only among active replicas, not durable actor history.** `Engine::add` (bridge lines68–71) rejects currently active equal client IDs; `cancel`/`reset` removes that protection. Reusing a client after cancellation/restart, or receiving independently authored remote blocks with an already used `(client,clock)`, is not checked. Yrs explicitly assigns client uniqueness to the caller (`src/doc.rs:140`, `:470`); `TransactionMut::apply_update` trims already known blocks before integration (`src/transaction.rs:862`), rather than providing an application provenance check. Gate: durable actor allocation/recovery across processes, independent clones, drafts, reset and restored state; intentional same-ID/different-content collisions must be rejected or quarantined without choosing whichever arrival happens first. Test inactive/restarted collisions, not just C29's live collision. Global rejection across all unrelated documents is also stronger than Yrs requires: the namespace must be defined per communicating document.

2. **A seed and an update have no field/document identity binding.** Every independently generated seed uses client1 and root `text` (bridge lines90–94). This is valid only inside separate, correctly routed documents with one agreed seed. Independent seeding of the same historical field, different historical strings sharing seed IDs, or cross-field application of an update has no rejection path. C14/C15 demonstrate separation when callers route correctly; they do not test misrouting. Gate: one deterministic, versioned seed derived from authoritative historical baseline, exact seed identity/hash, and an outer update envelope binding workspace/entity/item/field/occurrence. Check renamed fields, copied documents, recurrence successor identity, and seed conflicts. Never rely on identical visible strings, doc GUID, root name, or random-looking actor numbers as field authorization.

3. **Legacy scalar writers need an explicit accepted policy before text adoption.** The bridge cannot arbitrate an old whole-title/notes event against new character updates, and Yrs does not supply that product rule. A later legacy scalar write cannot silently replace merged history, be reinterpreted as a causal text delta, or become a second seed. Gate: specify which baseline begins the text epoch and how old writers fail safely thereafter; preserve all accepted stable-v3 fixture bytes/meaning and validate old decoder failure without advancing accepted history checkpoints. Include offline old-writer events arriving after new edits and after recovery. A01–A03 remain relevant unrun application gates.

4. **Plain-string rendering is not plain-text admission.** `apply_to` checks only rendered `get_string` length on a scratch clone (bridge lines73–84). Yrs `TextRef::get_string` intentionally includes only nondeleted string blocks and omits embeds/formatting (`src/types/text.rs:118`); foreign roots, nested types, rich attributes and invisible content therefore pass a rendered-text check and remain in full state. `new`/`restore` call `Replica::new` and apply arbitrary decoded seed/state directly (lines22–32,100–115), bypassing even that scratch length check. Gate: one ingress validator for seed, checkpoint, imported update and draft Save, restricted to the exact authorized text root and supported string/delete structures, including pending material whose parent is unresolved. Add foreign-root/map/array/XML/subdocument/embed/format and root-type-confusion cases; reject without any real-state or Undo-stack change. Include hidden deleted content and malformed references. A05 correctly remains open.

5. **Save's state-vector diff does not mean “only this draft's local changes.”** A draft stores a baseline vector but no source identity, and `save` accepts any target (bridge lines102–105,132–140). A captured draft can therefore be saved into a different field or another draft. Also, `apply` permits remote changes into the draft; subsequent Save's `encode_diff_v1(baseline)` includes all integrated postbaseline structs, regardless of transaction origin. Yrs documents that the diff includes the entire delete set and excludes pending updates (`src/transaction.rs:75–90`). Saving that result with origin `local` can attribute newly delivered remote work to the target's local Undo scope. C04/C23 apply incoming changes to the target, not to the draft, so they do not cover this case. Gate: bind draft to an immutable source/field identity and document allowed incoming updates while editing; prove ownership of the published transaction and of the Undo item. Test remote insert/delete arriving into a draft, unresolved dependencies, Save to unrelated target/source-equals-target, repeated Save, Save→Undo→Save, edit-after-Save and failed Save. Consume or advance the captured baseline deliberately; it currently remains reusable.

6. **Checkpoint pending retention is supported, but recovery and ownership remain unproved.** The bridge's `full()` uses `encode_state_as_update_v1`, which includes pending updates and pending delete sets through `merge_pending_v1` (`src/transaction.rs:140`,`:376`). C11's checkpoint behavior is therefore consistent with actual Yrs source; do not claim that this full encoding drops pending data. In contrast, bridge `diff` uses `encode_diff_v1(default)` and excludes pending data. Gate: make that distinction explicit in any future checkpoint/tail protocol; add pending delete-set, multiple missing dependencies and fresh-process recovery. Checkpoint schema currently has no authenticated hash/document binding and restores no Undo stack or draft baseline. C11/C32 destroy and rebuild a replica within the same native process, not a fresh-process durability test. A04 should distinguish full-state encoding from diff encoding rather than imply all checkpoints lose pending structs.

7. **Visible text, update, and retained-state budgets are conflated.** `MAX=65536` is both a UTF-16 visible-text bound and a binary decode bound. An accepted maximum-length ASCII seed needs binary header bytes beyond MAX; multibyte strings and retained tombstones can exceed it earlier. Local edits can grow historical full state beyond MAX even with short visible text, after which scratch cloning in `apply_to` decodes `r.full()` and rejects its own state. Full export/checkpoint has no corresponding output/retained-state limit. Gate: separate request bytes, incoming update bytes, visible field length, checkpoint/state bytes, pending bytes, root/struct count and total document count. Test self-generated roundtrip at boundaries, delete-heavy workloads, long histories, many small pending updates, and export/restore/apply after growth. C34's 2000 insertions into one field do not exercise these cases or the existing 500/10000 task field bounds.

8. **FFI and panic containment are narrower than production failure isolation.** `thread_local!` makes names/state belong to the caller OS thread; the ABI has no explicit engine/document handles or owner token. Different Dart isolates/threads can see different registries, and repeated `new/read/free` on one Python thread does not prove native threading behavior. `CStr::from_ptr` scans to NUL before the request byte limit, while `spike_free` requires the exact outstanding allocation once. `catch_unwind` does not protect invalid pointers, aborts/OOM, or prove transaction rollback after an engine panic; poisoned/mutated replicas are not retired. Gate: documented handle/owner/thread contract, length-bearing input, allocator/free ownership, isolation or bounded parser defense, invalid update fuzzing, cancellation/reentrancy/drop and fresh-process crash recovery. Scratch application is a useful check, but real apply/Undo can still panic and must not leave an apparently healthy replica. Yrs UndoManager unregisters document observers on Drop (`src/undo.rs:735`); lifetime/order must be proved by the chosen native owner rather than inferred from C33's response allocation cycles.

Undo origins are adapter-local metadata, not durable update ownership: Yrs captures by transaction origin and scope (`src/undo.rs:193–206`). Existing C22–C25 provide useful session examples. Further gates should cover two simultaneous drafts, a canceled draft receiving a late callback, actor reuse, Save failure preserving Undo/redo state, remote changes resolving during Undo, and stable user-visible operation receipts. Checkpoint/restart currently resets session Undo; decide and label that boundary. IME boolean/one sticky anchor tests do not validate real Flutter composition, selection ranges, reversed selections or delayed callbacks (N04 remains open).

## Other Yrs uses: recommendations only

| Area | Recommendation and reason |
| --- | --- |
| Checklist item title/notes | Good narrow candidate if text policy is accepted. Keep item UUID, deletion tombstone, parent completion and recurrence outside the text sequence; each field/occurrence needs its own identity binding. |
| Checklist order | Keep the approved relative-anchor event design initially. A Y.Array merges insertion/deletion, but moving a logical UUID by delete+insert can produce concurrent duplicate occurrences or delete/reinsert ambiguity. The reviewed Array API has insert/remove operations; sequence convergence alone does not enforce UUID uniqueness or permanent item deletion. Require dedicated move/delete/Undo semantics tests before a separate ordering change. |
| Tags | Preserve existing observed-remove set semantics. A Y.Map boolean/key replacement uses logical LWW with client seniority on concurrent writes (`src/types/map.rs:23`), which changes add/remove meaning; a Y.Array is not a membership set and admits duplicates. Text CRDT adoption does not justify tag migration. |
| Global/manual task order | Preserve deterministic anchor replay and its completed/Inbox/date-bucket rules. Yrs does not enforce those product constraints, and there is no evidence here that replacing working order events reduces complexity. Revisit only for a demonstrated ordering defect or explicit collaborative ordering requirement. |
| Structured schedule/assignee/completion | Keep explicit validated domain commands. Independently merged map keys can synthesize invalid schedule tuples or recurrence intent; opaque LWW map objects still replace a whole value. Neither supplies schedule validation, derived successor identity, completion ownership or deletion precedence. |
| Counters | Consider an operation-based additive counter only for a future actual increment/decrement requirement. `Y.Map.get` plus numeric replacement can lose concurrent increments; a map is not a PN-counter. No relevant counter domain or acceptance cases exist in this spike, so no adoption recommendation now. |
| Future saved freeform text | Potentially reuse the narrow validated text adapter after it passes the gates, with document identities and length/storage policies specific to that feature. Do not generalize the current C ABI into a whole-app persistence framework. |

The next useful implementation work is a small adversarial/ownership test tranche addressing findings1,2,4,5,7. Production protocol/native packaging and UI evidence should remain separately labeled gates; 34 passing synthetic ctypes cases do not establish them.
